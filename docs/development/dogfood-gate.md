# Ручная диагностика сбоя в Proteus

Воспроизведите проблему в той же рабочей папке и с тем же профилем.
Выберите короткое действие с наблюдаемым результатом. Например, если зависает
запрос разрешения, повторите вызов нужного инструмента и проверьте ответ на него.

## Воспроизведение

1. В папке проекта запустите `proteus --config PROFILE doctor`, подставив имя
   или путь к профилю. Команда проверяет конфигурацию и сохранённые сессии этой
   рабочей папки без обращения к модели.
2. Откройте ту же папку в Desktop с этим профилем и повторите действие. Проследите,
   дошёл ли запрос до инструмента, появилось ли подтверждение и вернулся ли результат.
   Для ошибки при записи сравните результат с изменением файла.
3. Найдите каталог нужного чата по полю `session_dir` в ответе `GET /sessions`.
   Прочитайте отчёт для этой сессии. [Устройство хранилища и журнала](../guides/runtime-and-events.md#session-store).

```sh
proteus --config PROFILE eval report "/path/to/session-dir"
```

## Где искать причину

| Что наблюдается | Что проверить |
|---|---|
| `doctor` сообщает об ошибке | Профиль, модуль или каталог сессии, указанный в сообщении. |
| В журнале есть результат инструмента, но чат его не показал | Сравните историю этой сессии в app-server с лентой Desktop. [История и события](../guides/runtime-and-events.md#history). |
| Разрешение было выдано, но действие завершилось ошибкой | Найдите ответ политики и результат вызова в том же ходе. [Разрешения и проверки инструментов](../guides/security-and-policy.md). |
| После отмены или тайм-аута пропал финальный статус | Найдите `TurnSettled` в журнале. Перезапустите app-server и проверьте статус через `GET /history` для того же `session_dir`. |

Для корневого хода со статусом `Success` или `Error` без доставленных steering/follow-up
можно повторить workflow по журналу. Если ходов несколько, укажите нужный `--turn-id`.
[Условия воспроизведения](../guides/runtime-and-events.md#workflow-replay).

```sh
proteus --config PROFILE replay workflow "/path/to/session-dir" --turn-id TURN_ID --json
```

Для передачи сбоя достаточно указать профиль, действие, ожидаемый и фактический
результат и место в журнале, где впервые видно расхождение.
