## API записи и пределы

`workspace_file_for_write` остаётся явно truncating API: после проверки inode
ошибка последующей записи сама по себе не откатывает файл. Для полной замены
используется `workspace_file_for_atomic_write`, `Write::write_all`, затем
`WorkspaceAtomicFile::commit`. До commit исходный файл не меняется, Drop
удаляет частичную staging-копию; commit синхронизирует файл, переименовывает
его через pinned parent fd и синхронизирует каталог. Изменение внешнего
hardlink inode при этом исключено самим replacement, а не эвристикой имени.
Изменение shared inode после `nlink`-проверки другим доверенным процессом не
объявляется невозможным. Отказ directory sync после rename может означать,
что новый файл уже опубликован, но durability не подтверждена.

## Документация и исключённые утверждения

Исправлены все восемь групп текущего doc drift: model/v13, самостоятельные
installed binaries, optional model, disabled tool inventory, bounded-age
semantic polling, request-only interrupted-turn marker, doctor bootstrap
side effects, реализованный ACP и авторитетные pending/session snapshots.
Исторические archive/research материалы не переписаны как текущий контракт.

Ни trust default, ни смешанный restricted профиль, ни возможность исполнения
кода выбранного модуля не объявляются новыми уязвимостями. Отвергнутые в
аудите raw-arguments и child transcript hypotheses не исправлялись без
доказанного production path. Дополнительные slots и bundle manifest остаются
продуктовыми предложениями; дефекты других репозиториев в этом ledger не закрыты.
