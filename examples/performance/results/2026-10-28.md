## Установившаяся память

Значения в MiB, сумма дерева процессов. GUI — native, Core, modules и extensions. HTTP — десять независимых Core с модулями. Active — Rust AgentControl parent и все десять peers с модулями; Python измеритель и GUI исключены. Idle/GUI — медиана трёх независимых повторов; active — один полный прогон с тремя ходами каждого peer.

SwapPss измеряемых процессов во всех успешных сценариях — 0. RSS повторно учитывает общие страницы; для суммарной оценки предпочтителен PSS.

Активный сценарий сохраняет все 5 000/50 000 сообщений в UI/journal, но начинает model history с последних 100 исходных сообщений после синтетического compaction checkpoint. Качество summarizer этим не измеряется. Настоящие AgentControl spawn/wait/resume идут через явно выделенный benchmark exec adapter к preseeded sessions; это не штатный disk-resume AgentControl. Payload read_file — 32 KiB, fake delay 500 мс, max_parallel/resident cap 10. В каждом из четырёх активных случаев подтверждены 10 параллельных model calls и 30 завершённых/replay-совпавших ходов.

## Сборка

Здесь отдельный baseline Desktop `50f8b53b6868` против `af553b6e5fda`: он изолирует выделение diff/tabs crates. В обоих случаях profile fast, jobs=2, прежний target сохранён. После warmup трижды выполняется одинаковая содержательная правка panic-строки parser: `a file was started` → `a diff file was started`, затем восстановление исходных bytes и отдельная восстановительная сборка.

| После прогрева | До, с: медиана [min–max] | После, с: медиана [min–max] |
|---|---:|---:|
| noop | 0.46 [0.45–0.61] | 0.46 [0.45–0.47] |
| edit | 5.18 [4.84–6.42] | 4.88 [4.68–5.32] |

Сильное ускорение полной пересборки приложения этим опытом не подтверждено: edit-медиана улучшилась примерно на 6%, диапазоны перекрываются. Warmup 74,36/6,97 с не является честным сравнением архитектуры: история существовавшего кэша различалась. Сравниваются только одинаковые операции после успешного прогрева.

Новая portable release без архива заняла 5:04,25 на сохранённых dependency caches (не clean build). Release и fast между собой в таблице не сравниваются.

## Проверки и ограничения

- 16 лёгких проверок постоянных инструментов прошли; Rust examples/driver собраны, rustfmt/Python checks прошли.
- 24 финальных GUI-запуска и 24 цикла десяти HTTP backends прошли. Проверены точные session IDs, UI count/cursor, tail IDs/text и неизменность canonical journal/blobs при чтении.
- 120 активных ходов проверены workflow replay; после ходов cold HTTP подтверждает сохранение исходных 5k/50k UI messages и head/tail anchors.
- Отдельный несжатый контекст из 50 000 сообщений у одного настоящего peer завершился ошибкой `coding.codex_loop: run lost its component: Resource` на обеих версиях. Он не включён в таблицу успешной нагрузки. В process host имеется лимит frame 8 MiB; Resource-сообщение само по себе не раскрывает конкретный исчерпанный лимит.
- Процессы тестов и фоновый GUI-сеанс завершены. Cargo target не очищался. Derived SQLite caches упакованы с проверкой каждого SHA256, исходники и canonical inputs сохранены.
