# Proteus Core

Здесь живут runtime, публичные контракты, CLI и app-server. Реализации моделей,
инструментов и хранилищ находятся в [Proteus-modules](https://github.com/Proteus-harness/Proteus-modules).
Действующее устройство и планы собраны в [указателе документации](docs/README.md).
При изменении поведения обновляйте соответствующий справочник на русском языке.

## Изменение контракта

Core обращается к модулю через контракт слота. Общие типы лежат в
`crates/proteus-contracts`, особенности провайдера остаются в его реализации.
Выберите [существующий слот](docs/architecture/modules.md#слоты-и-их-выбор).
Если его контракт не выражает нужное поведение, см. [порядок добавления слота](docs/architecture/slot-governance.md).

Модули работают отдельными процессами. Права каждого вызова определяют слот
и контекст вызова, даже когда один процесс предоставляет несколько реализаций.
Вызовы инструментов проходят через `ToolRegistry`, `ApprovalPolicy` и `ToolSafety`.
По умолчанию процесс работает с правами пользователя. Ограничения ОС включаются
для конкретного компонента или stdio MCP. См. [протокол модулей](docs/architecture/process-module-architecture.md)
и [режим ограниченного запуска](docs/guides/security-and-policy.md).

В альфа-версии черновые форматы можно менять вместе со всеми производителями,
потребителями, конфигурациями и тестами. Устаревшую форму удаляйте в той же правке.
Для режимов совместимости с другим агентом сверяйте поведение и ошибки с оригиналом.
Для Codex есть [база сравнения](docs/development/codex-baseline.md).

## Проверка и поставка

Запускайте тесты затронутого пакета через `./scripts/test.py -p PACKAGE`.
При изменении контракта проверьте обе стороны и заменяемость реализаций.
Нужные сценарии перечислены в [матрице проверок](docs/development/testing.md#evidence-matrix).
Выигрыш в памяти, времени или CPU подтверждайте замером на сопоставимой нагрузке.
Для работы с памятью есть [отдельное руководство](docs/development/memory.md).

Проверенную правку оформляйте отдельным коммитом. После изменения исполняемого
кода обновите backend в рабочей поставке по [руководству Desktop](https://github.com/Proteus-harness/Proteus-desktop/blob/main/BUILDING.md#выбор-компонентов).
